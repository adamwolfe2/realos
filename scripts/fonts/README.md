# Web font subsets

Inter and JetBrains Mono are self-hosted subsets in `public/fonts/`, declared in
`app/fonts.generated.css` and preloaded from `app/layout.tsx` via
`app/fonts.generated.ts`. All three are generated by `subset-fonts.py`: do not
edit them by hand. Nothing runs at build time.

What the script does, per font:

- limits the weight axis to what is used (Inter 400-900 with opsz 14-32 kept,
  JetBrains Mono 400-800), from pinned upstream files matching Google's versions;
- keeps only the OpenType features browsers apply by default plus `tnum`;
- drops hinting (Google's files had none either), keeps glyph names (see below);
- splits into one file per Google subset under one family name, mapping
  exactly the characters Google's files did (`google-coverage.json` is a
  snapshot of what next/font/google served):

| file | contents | loading |
| --- | --- | --- |
| `*-core` | Google's latin subset: ASCII, Latin-1, common punctuation | preloaded on every page |
| `*-ext` | Google's latin-extended subset | only when a page has one of its characters |
| `*-vietnamese`, `*-greek`, `*-greek-ext`, `*-cyrillic`, `*-cyrillic-ext` | the other scripts | same |

Each `unicode-range` lists only characters its file contains. Google's latin
range also claimed characters its file lacked (U+2000-2008 spaces, U+2011
non-breaking hyphen, ...), which Chrome then drew with Inter's own glyphs; those
now come from the fallback font. No current page or source string uses them.

`font-display: swap` and the size-adjusted Arial fallback faces are copied
unchanged from what next/font/google generated. Characters Google's files never
had (arrows, stars, CJK) still come from the fallback stack.

Gotchas found while building this (each verified with pixel diffs):

- Chrome shapes each font file as its own run, so seams must match the old ones
  or kerning changes across them. That is why core = Google's latin set, not ASCII.
- Without `post` glyph names, Chrome renders 11-18px text slightly differently.
- Each file must map the same characters as its Google counterpart (Google's
  latin file carried five combining marks it did not claim), or small text
  rasterizes differently. That is also why the other scripts are not merged.
- fontTools 4.68 cannot subset the raw upstream variable TTFs (gvar KeyError);
  saving once through the instancer first avoids it.
- fontTools stamps the current time into `head.modified` on save, which would
  rename every file on each rerun and drop visitors' caches. The script pins it
  to the upstream timestamp, so reruns are byte-identical.

## Rerun when

- a weight outside the ranges above, a new OpenType feature
  (`font-feature-settings`, `font-variant-*`) or `font-variation-settings` is
  introduced: the script exits with an error naming it until the config changes;
- the pinned upstream font version changes.

Copy changes alone never need a rerun: the files cover everything Google did.

## How

```sh
python3 -m venv .venv-fonts && .venv-fonts/bin/pip install fonttools brotli pillow
pnpm build && pnpm start -p 3100        # separate shell
node scripts/fonts/collect-usage.mjs http://localhost:3100 scripts/fonts/usage.json
.venv-fonts/bin/python scripts/fonts/subset-fonts.py
```

Verify: run the previous commit's build on :3100 and this one on :3200, then

```sh
node scripts/fonts/pixel-diff.mjs http://localhost:3100 http://localhost:3200 /tmp/font-shots
.venv-fonts/bin/python scripts/fonts/compare.py /tmp/font-shots
```

Commit `public/fonts/`, `app/fonts.generated.*` and `scripts/fonts/usage.json`.
